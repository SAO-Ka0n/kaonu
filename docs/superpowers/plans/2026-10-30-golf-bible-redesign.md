# 골프 바이블 프로토타입 재설계 계획

근거: `DESIGN-IS-2026-10-30/04-handoff-prompt.md` (REDESIGN, 16/30). 숫자, 용어, 체계, 접근성, 중복 문제는 `05-fixes.md`에서 이미 고쳤다. 이 계획은 남은 핵심인 **주 흐름**을 목적에서부터 다시 짠다.

## Primary goal

연습장 타석에 선 골퍼가 앱을 열고 버튼 하나를 누르면, 한 손으로 오늘 연습을 한 단계씩 따라가고, 실제로 친 공과 테스트 결과가 그대로 기록된 채 끝난다.

## 현재 vs 재설계 (홈 주 흐름)

```
현재                                   재설계
┌──────────────────────┐              ┌──────────────────────┐
│ 오늘은 피니시 3초      │              │ 오늘은 피니시 3초      │
│ [오늘 레슨 카드]       │              │ [오늘 레슨 카드]       │
│  약 45분 · 공 50 · 0/5 │              │  약 45분 · 공 50 · 0/5 │
│  [영상 보고 시작]      │              │  [ 연습 시작 ]  ← 하나  │
│ 오늘 연습              │              │ 오늘 연습 (미리 보기)   │
│ ○ 드릴 1  ← 체크만     │              │  1 드릴 1   공 20개    │
│ ○ 드릴 2              │              │  2 드릴 2   10회       │
│ ...                   │              │  눌러서 그 단계부터     │
└──────────────────────┘              └──────────────────────┘
 공을 쳤는지와 무관하게                  ↓ 연습 모드 (전체 화면)
 체크 한 번으로 "완료"                  ┌──────────────────────┐
 테스트는 나중에 숫자를                  │ ✕   2/5  ▬▬▬▭▭       │
 기억해서 입력                          │ 치고 3초 버티기        │
                                       │ 7번 아이언 ...         │
                                       │      12 / 20 공       │
                                       │ ┌──────────────────┐ │
                                       │ │   한 개 쳤어요 +1  │ │ ← 화면 아래 절반
                                       │ └──────────────────┘ │
                                       │ [이전]        [건너뛰기]│
                                       └──────────────────────┘
                                        테스트 단계: [성공] [실패]를
                                        공마다 누름 → 결과 자동 계산
                                        마지막: 요약 + 회고 한 화면
```

## 화면 지도 (4개 탭 유지, 사용자 결정)

- 홈 → 연습 모드(전체 화면, 탭바 숨김) → 끝 요약/회고 → 홈
- 홈 → 미리 보기 항목 누름 → 연습 모드(그 단계부터)
- 교본 → 현재 단원 레슨 → 레슨 화면(영상, 체크포인트, 드릴 읽기 전용, 오늘 레슨이면 "이 레슨으로 연습 시작")
- 교본 → 통과한 단원 → 단원 화면 → 레슨 화면
- 교본 → 통과 테스트 → 테스트 화면(설명 + "테스트 시작" → 연습 모드의 테스트 단계만)
- 기록, 멘탈: 변경 없음 (기록의 공 개수만 실제 친 공 기준)

## 상태 체크리스트

| 상태 | 어디서 |
|---|---|
| 빈 | 첫 실행(온보딩), 기록/멘탈 빈 목록 (기존 유지) |
| 로딩 | 해당 없음: 저장소 읽기가 동기라 첫 화면 전에 끝남 (계획에 명시, 화면 없음) |
| 오류 | 저장 실패 안내(기존), 연습 모드 안에서도 보임 |
| 성공 | 단계 완료 표시, 끝 요약, 테스트 통과/미통과 결과 |
| 포커스 | 연습 모드 진입 시 단계 제목, 단계가 바뀔 때마다 제목, 닫으면 홈 시작 버튼 |
| 비활성 | 목표에 도달한 카운터, 첫 단계의 "이전" |

## 저장소 이전 (v2 → v3)

- `DayLog`에 `counts: Record<항목 id, number>`(친 공/반복 수)와 `shots: Record<단원 id, boolean[]>`(테스트 공별 성공 여부)를 더한다.
- `load()`가 `golf-bible-proto-v2`를 읽으면 각 날에 빈 `counts`, `shots`를 채워 v3 키로 저장한다. v2 키는 지운다.
- 옛 기록의 체크된 드릴은 공 개수를 계획값(`balls`)으로 센다. 새 기록은 실제 누른 수로 센다.

## 폐기 기준

- 홈의 체크 목록 조작은 연습 모드가 모든 항목 종류(공, 반복, 시간, 멘탈, 테스트)를 처리하면 미리 보기로 바뀐다.
- 테스트 화면의 "성공 개수 입력기"는 테스트 단계가 공별 기록을 하면 없앤다.
- 플래그로 두 흐름을 함께 두지 않는다.

## Phase 1: 단계 모델과 저장소 v3

> **How this serves the primary goal:** "한 단계씩"과 "실제로 친 공"을 화면이 아니라 순수 함수 한 곳에서 정의해야 홈, 연습 모드, 기록이 같은 숫자를 보여 준다.

할 일:
1. `progress.ts`에 `Step` 타입과 `stepsFor(parts, day, mental)`를 추가한다. 종류: `balls`(목표 공 수), `reps`(목표 횟수), `timer`(목표 분), `mental`(한 번 확인), `test`(공별 성공/실패, of개). `routineFor`:108의 항목 순서를 그대로 쓴다.
2. `DayLog`에 `counts`, `shots`를 더하고, `ballsOf`:143은 `counts`가 있으면 그 값을, 없으면 체크된 드릴의 `balls`를 센다. 테스트 공은 `shots` 길이로 센다.
3. `store.tsx`에 액션 `count{id, delta, target}`(목표에 닿으면 체크), `shot{chapterId, ok}`(of개가 차면 TestResult 자동 기록), `undoShot`를 더한다. `load`:97에 v2→v3 이전.

검증: `node --test --experimental-strip-types prototype/tests/` 통과, `tsc --noEmit` 통과.

> **How this serves the primary goal:** 앱을 연 사람이 누를 버튼이 하나뿐이어야 바로 시작한다.

할 일:
1. 홈: 시작 버튼 문구를 상태에 따라 "연습 시작" / "이어서 하기 (k/N)" / "다시 보기"로. 오늘 연습 목록은 체크 버튼 대신 미리 보기 줄(누르면 그 단계부터 연습 모드). 공 수는 진행 중이면 "칠 공 / 친 공"을 함께.
